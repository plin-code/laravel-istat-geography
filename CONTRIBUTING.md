# Contributing

## Build and test

You need PHP 8.4 or higher and [Composer](https://getcomposer.org). From the root of the project:

```bash
composer install
composer test        # the whole suite, no network needed
composer analyse     # PHPStan
composer format      # Pint, fixes the code style
```

The tests mock every HTTP request, so they never call ISTAT or any other server.

Run the three commands before opening a pull request. The same tests and the same analysis run on GitHub for every pull request and for every push to `main`.

## Commits and branches

- No commit on `main`. Work on a branch named `type/short-kebab-description`, for example `fix/bel-code-on-update`.
- Message format: `type(scope): description`, then a blank line, then an optional body.
- `type`: feat, fix, docs, test, refactor, perf, chore.
- `scope`: mandatory, lowercase, one of: import, update, cap, coordinates, models, commands, config, migrations, boost, tests, scripts, readme, docs, ci, deps, release.
- `description`: imperative, lowercase, no final period, 50 characters at most.
- Body: optional, most commits have none. When written: why, not what, with lines of 72 characters at most. It is mandatory only for an incompatible change: `BREAKING CHANGE:` on its own line in the body, and `!` after the scope in the title.
- One change per commit. Documentation changes go in the same commit as the code they describe.
- Never write: issue or pull request numbers, `Co-authored-by`, "Generated by", emoji, or any mention of the tool that wrote the commit.

Examples:

```
fix(update): save bel_code on new municipalities
feat(coordinates): add municipality coordinates
docs(readme): fix requirements, cap path and tables
```

### The hook

The hook in `.githooks/commit-msg` checks the message of every commit against these rules, and refuses the commit when one is broken. Turn it on once, in your clone:

```bash
git config core.hooksPath .githooks
```

A commit that the hook refuses is fixed, never made with `--no-verify`.

GitHub runs the same hook on every commit of a pull request, so a commit made without it is caught there. The hook cannot check the imperative mood or whether a commit holds one change. That is left to the review.

A `git commit --fixup` passes on a branch and fails on GitHub, so squash it before asking for the merge (`git rebase -i --autosquash main`).

### Fixing a refused commit

```bash
git commit --amend                 # the last commit
git rebase -i main                 # an older commit: mark it with "reword"
git push --force-with-lease        # update the pull request
```

## Pull requests

Pull requests are merged with a rebase: the commits reach `main` as they are, with their author. This is why every commit must follow the rules, not only the title of the pull request.
